# Compliance

## What Aegis will not tell you

Aegis does not assert that you are compliant with anything. It reports that
findings intersect specific controls, and it attaches the control text so a
qualified assessor can read the evidence side by side.

```
> This is an automated assessment of technical control evidence produced by
> Aegis. It is decision support for a qualified assessor. It is not a
> certification, and it does not attest that the organisation complies with
> any framework listed.
```

A scanner that claims compliance is worse than no scanner, because people act on
the claim.

### Three distinctions the report maintains

**"No findings" is not "pass."**
Aegis did not find anything. Only an auditor can attest that a control operates
effectively. The status is labelled `No findings (not attested)` in every
rendering.

**"Not operating effectively" is reserved.**
Asserted only for critical findings with concrete evidence attached.

**Limitations are stated, not buried.**
Every attestation carries them.

## Generating an attestation

```bash
aegis report . --compliance \
  --organisation "Acme Inc" \
  --system "Customer Support Agent" \
  --owner "security@acme.com" \
  --format html \
  --output attestation.html
```

Markdown works the same way:

```bash
aegis report . --compliance --organisation "Acme Inc" --format markdown
```

Framework subset:

```bash
aegis report . --compliance --framework eu-ai-act --framework gdpr
```

## What a strong control looks like

The report states what an assessor will expect for each control. For example,
for EU AI Act Art. 14 (Human oversight):

> Evidence an assessor will expect: Evidence a human can meaningfully intervene,
> override, or stop the system.

That sentence is the point of the artefact. A finding says "your agent takes
irreversible actions with no approval gate". The control text says what the
regulation requires. The evidence expectation says what closes it.

## Interpreting the posture

| Posture | Meaning |
|---|---|
| `critical` | At least one control indicated as not operating effectively |
| `poor` | No critical failure, but three or more controls carry findings |
| `fair` | No critical failure, one or two controls carry findings |
| `good` | No findings intersected the assessed controls — **not an attestation** |

## Scope

Aegis assesses **technical** control evidence only. It does not evaluate:

- Organisational or procedural safeguards
- Physical security
- Human resource controls
- Most of what a SOC 2 Type II opinion or ISO certification covers

If your goal is a certification, Aegis produces the technical evidence pack an
assessor needs. It is not the assessor.
